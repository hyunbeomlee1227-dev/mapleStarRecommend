# 공개 웹 서비스 배포

Status: ready-for-agent

## Problem Statement

현재 애플리케이션은 공개 저장소에 있으며 운영 실행과 컨테이너 구성을 갖췄지만, 실제 인터넷 사용자가 접속할 수 있는 배포 환경과 이를 반복 검증하는 자동화가 없다. 운영자는 로컬에서만 확인한 결과가 공개 환경에서도 동일하게 동작하는지, NEXON Open API 키가 이미지나 응답에 포함되지 않는지, 프록시 뒤에서 사용자별 요청 제한과 일일 사용량 기록이 유지되는지 확신할 수 없다.

## Solution

GitHub의 변경마다 운영 컨테이너를 빌드하고 실제로 실행해 상태 확인, 메인 화면, API 응답과 비밀값 비노출을 검사한다. 검증된 이미지는 단일 인스턴스의 공개 웹 서비스로 배포하고 NEXON Open API 키는 호스팅 플랫폼의 비밀 환경 변수로만 제공한다. 공개 주소에서 캐릭터 조회와 요청 제한을 검증하며, 영구 볼륨으로 일일 사용량 기록을 보존하고 운영 및 복구 절차를 문서화한다.

## User Stories

1. As a 서비스 사용자, I want 인터넷의 공개 주소로 서비스에 접속하고 싶다, so that 로컬 개발 환경 없이 장비 추천 기능을 사용할 수 있다.
2. As a 모바일 사용자, I want 공개 주소에서도 동일한 화면을 사용하고 싶다, so that 기기와 관계없이 캐릭터를 조회할 수 있다.
3. As a 서비스 사용자, I want 공개 서비스에서 캐릭터 이름을 조회하고 싶다, so that 내 보스용 장비를 분석할 수 있다.
4. As a 서비스 사용자, I want 서버 장애 시 안전한 오류를 받고 싶다, so that 비밀 정보나 내부 오류 내용을 보지 않는다.
5. As a 서비스 운영자, I want 모든 변경에서 운영 이미지를 자동으로 빌드하고 싶다, so that 배포 전에 깨진 구성을 발견할 수 있다.
6. As a 서비스 운영자, I want 운영 컨테이너의 상태 확인 경로를 검사하고 싶다, so that 호스팅 플랫폼이 정상 인스턴스만 서비스하게 할 수 있다.
7. As a 서비스 운영자, I want 빌드된 메인 화면과 정적 자산을 검사하고 싶다, so that API만 살아 있고 화면은 깨진 배포를 차단할 수 있다.
8. As a 서비스 운영자, I want 운영 API 응답을 검사하고 싶다, so that 공개 서버와 프런트엔드가 같은 배포에서 동작함을 확인할 수 있다.
9. As a 서비스 운영자, I want API 키가 이미지, 번들, HTML과 응답에 포함되지 않음을 검사하고 싶다, so that 공개 배포로 인증 정보가 유출되지 않는다.
10. As a 서비스 운영자, I want API 키를 호스팅 플랫폼의 비밀 환경 변수로 등록하고 싶다, so that 저장소와 이미지에 인증 정보를 남기지 않는다.
11. As a 서비스 운영자, I want 새로 발급한 API 키만 운영에 사용하고 싶다, so that 과거에 노출된 키를 재사용하지 않는다.
12. As a 서비스 운영자, I want GitHub의 기본 브랜치에서 검증된 변경만 배포하고 싶다, so that 공개 서비스가 재현 가능한 소스 상태를 따른다.
13. As a 서비스 운영자, I want 리버스 프록시 단계를 명시하고 싶다, so that 사용자별 요청 제한이 실제 클라이언트 IP에 적용된다.
14. As a 서비스 운영자, I want 전달 IP 헤더 위조로 요청 제한을 우회하지 못하게 하고 싶다, so that 외부 API 사용량을 보호할 수 있다.
15. As a 서비스 운영자, I want NEXON API 일일 사용량 기록을 재시작 후에도 유지하고 싶다, so that 재배포로 일일 제한이 초기화되지 않는다.
16. As a 서비스 운영자, I want 서비스 인스턴스를 하나로 제한하고 싶다, so that 파일 기반 사용량 기록이 여러 인스턴스에서 충돌하지 않는다.
17. As a 서비스 운영자, I want 배포 상태와 최근 로그를 확인하고 싶다, so that 장애 원인을 빠르게 구분할 수 있다.
18. As a 서비스 운영자, I want 실패한 배포에서 이전 정상 버전으로 복구하고 싶다, so that 사용자 장애 시간을 줄일 수 있다.
19. As a 서비스 운영자, I want 배포 환경 변수 목록과 안전한 설정 방법을 확인하고 싶다, so that 운영 설정을 누락하지 않는다.
20. As a 기여자, I want 로컬 개발과 운영 배포의 차이를 문서에서 확인하고 싶다, so that 외부 바인딩이나 비밀값 처리를 잘못 설정하지 않는다.

## Implementation Decisions

- 프런트엔드와 API는 현재와 같이 하나의 Express 운영 프로세스와 동일 출처에서 제공한다.
- 운영 산출물은 Node.js 22 기반 다단계 컨테이너 이미지로 만든다.
- 운영 프로세스는 호스팅 플랫폼이 지정한 포트와 모든 네트워크 인터페이스에 바인딩한다.
- 상태 확인 계약은 인증이 필요 없는 `GET /healthz`의 성공 응답이다. 응답에는 구성값과 비밀값을 포함하지 않는다.
- 자동 검증은 운영 컨테이너를 실행한 뒤 상태 확인, 메인 HTML, 정적 자산과 서버 상태 API를 공용 HTTP 경계에서 검사한다.
- 자동 검증에는 실제 NEXON API 키를 사용하지 않는다. CI 전용 표식 값을 런타임에만 주입하고 HTML, 정적 자산 및 응답에 나타나지 않는지 검사한다.
- 기본 프록시 신뢰 단계는 0이다. 선택한 호스팅 플랫폼의 실제 프록시 구성을 확인한 뒤 환경 변수로 정확한 단계를 설정한다.
- 실제 NEXON Open API 키는 저장소, 컨테이너 이미지, 빌드 인수와 클라이언트 환경 변수에 넣지 않고 호스팅 플랫폼의 비밀 저장소에 등록한다.
- 공개 배포에는 과거 대화에 노출되지 않은 재발급 키를 사용한다.
- 현재 파일 기반 일일 사용량 제한을 유지하므로 운영 인스턴스는 하나로 고정하고 런타임 디렉터리에 영구 볼륨을 연결한다.
- GitHub 기본 브랜치의 검증 성공을 배포 입력으로 사용한다. 자동 배포 실패는 이전 정상 배포를 유지해야 한다.
- 공개 배포 대상은 우선 Render의 단일 웹 서비스로 정한다. 다른 플랫폼으로 변경할 경우 동일한 컨테이너, 상태 확인 및 비밀 환경 변수 계약을 유지한다.

## Testing Decisions

- 가장 높은 테스트 경계는 실제 운영 컨테이너가 노출하는 HTTP 인터페이스다. Dockerfile 내용이나 Express 내부 설정값 자체보다 실행 결과를 검증한다.
- 스모크 테스트는 재시도 가능한 방식으로 서버 준비를 기다린 후 상태 확인, 메인 HTML, 연결된 정적 자산과 서버 상태 API를 요청한다.
- 비밀값 검사는 CI 전용 표식이 모든 관찰 가능한 HTTP 응답에 없는지 확인한다.
- 기존 서버 계약 테스트에서 상태 헤더와 프록시 요청 제한을 검증하고, 기존 Playwright 테스트에서 데스크톱과 모바일 핵심 흐름을 검증한다.
- 공개 배포 검증은 공개 URL의 상태 확인과 실제 캐릭터 조회를 수행하되 API 키, OCID 또는 사용자 장비 데이터를 테스트 로그에 출력하지 않는다.
- 사용량 보존 검증은 영구 볼륨을 유지한 채 컨테이너를 재시작하고 일일 카운터가 유지되는 외부 동작을 확인한다.
- 좋은 테스트는 공개 입력과 응답만 사용하고 내부 함수, 파일 배치 또는 호스팅 제공자의 구현 세부사항에 결합하지 않는다.

## Out of Scope

- 여러 지역 또는 여러 인스턴스로의 수평 확장
- 파일 기반 사용량 제한을 Redis나 데이터베이스로 이전하는 작업
- 회원가입과 서버 기반 사용자 데이터 저장
- 커스텀 도메인 구매와 유료 요금제 계약
- NEXON API 이외의 외부 서비스 자격 증명 추가
- 장비 추천 엔진의 계산식 또는 화면 기능 변경

## Further Notes

- API 키 재발급과 Render 계정의 비밀 환경 변수 등록은 운영자의 권한이 필요한 단계다.
- 무료 또는 휴면 전환이 있는 호스팅 요금제는 첫 요청 지연과 영구 디스크 지원 여부를 배포 전에 확인해야 한다.
- 컨테이너 검증은 Docker 엔진이 필요한 관계로 로컬 Docker Desktop이 꺼져 있어도 GitHub Actions에서 재현 가능해야 한다.
